# 文件标签使用说明

文件标签可以给本机任意文件和文件夹贴上一组标签，之后按标签找回它们。标签集中保存在 Harness 主目录下的一个数据库里，不会在你标记的文件旁写任何东西。你可以在对话中让模型打标签，也可以在右侧栏浏览和搜索。

## 启用插件

1. 打开左侧栏的 **插件**。
2. 找到 **文件标签** 并启用。

该 bundle 会加载两部分：标签存储与模型工具，以及右侧栏的 **标签** 页面。

bundle 默认关闭，新 profile 在启用前不会做任何标记。禁用会移除工具与面板，但保留数据库，再次启用时标签仍在。

## 在对话中打标签

直接用自然语言告诉模型即可。它调用文件标签工具，这些工具接受绝对路径：

- “给 `~/notes` 和 `~/notes/today.md` 打上 work 标签。”
- “给 `~/notes/today.md` 加一个 draft。”
- “去掉 `~/notes/today.md` 的 draft。”
- “找出带 work 但没有 archive 的文件。”

标签只能是一个词：不能包含空格或括号。`and`、`or`、`not` 保留给表达式。标签在第一次使用时创建，在最后一个文件或文件夹移除它时删除。

## 使用“标签”页面

打开右侧栏，在引导页选择 **标签**。

- 顶部列出所有标签及其路径数量。在过滤框输入可以缩小芯片范围。
- 点击芯片把它加入标签表达式；再点几个芯片会以 `and` 组合。再次点击已选芯片可移除。
- 也可以直接输入表达式，例如 `work and not archive`。手动输入会替换芯片选择，两者不会互相矛盾。
- 结果列出每个路径及其标签。表达式下方的路径过滤只过滤当前列表，不再请求宿主。
- 每个结果有一个 **添加** 输入框，输入标签名并提交即可附加。标签上的 `×` 会从该路径移除它。
- Desktop 上每个结果还有 **打开**，用默认应用打开该路径。Web 不显示“打开”。

写入会在宿主成功后刷新该行。若宿主拒绝，原状态保留，面板会显示错误。

## 表达式语法

表达式用 `and`、`or`、`not` 和括号组合标签名：

- 优先级从高到低为 `not`、`and`、`or`。
- `work and not archive` 查找带 work 但不带 archive 的路径。
- `(draft or review) and work` 要求带 work，并且带 draft 或 review 中至少一个。
- 标签名区分大小写：`Work` 与 `work` 是两个不同标签。
- 表达式为空时不显示结果；请选择芯片或输入表达式。

一次搜索最多返回 200 条路径，按路径排序。

## 数据存放位置

数据库默认位于 `$DSH_HOME/data/filetags.db`（未设置 `DSH_HOME` 时为 `~/.dsh/data/filetags.db`），首次使用时以仅所有者可读写的权限创建。文件标签 bundle 会显式传入该路径，因此面板与模型工具始终读写同一个存储。

备份或迁移标签：先停止 Harness，复制 `filetags.db`（以及同目录下的 `filetags.db-wal`），再放回同一路径。Harness 运行时不要直接编辑数据库。

## 已知限制

- **不跟随移动。** 重命名或删除已标记路径后，标签仍留在数据库里，搜索可能显示已不存在的路径。请取消该路径的标签，或等待后续支持移动跟随的版本。
- **每个宿主一个数据库。** bundle 使用固定路径，两个宿主只有指向同一文件时才共享标签。
- **仅绝对路径。** 标签按输入时的路径保存，相对路径会被拒绝。
- **没有标签值、颜色或分组。** 本版本的标签只是普通名称。
- **Web 不能打开路径。** 用原生应用打开文件或文件夹需要 Desktop 宿主。
- **没有缺失路径状态。** 文件已被删除的行暂时不会被标记。
